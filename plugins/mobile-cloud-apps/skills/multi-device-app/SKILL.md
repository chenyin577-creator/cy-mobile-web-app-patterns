# CY 手机网页版 APP 常用开发模式

把「换一台手机能接着用」写成一个看得见的结果。先从当前项目找出正式入口、身份服务、云数据源，以及用户最怕丢的一项记录。沿用用户已经给出的答案。新项目若仍有关键歧义，一次问一个能改变方案的问题，例如「手机 A 和 B 同时修改一条记录，你希望保留哪些内容？」

## 开工时沿用什么

- 用户说「用我已有的云端数据库」时，先查当前项目的部署说明、环境名称及连接配置的**引用**，认清云服务、实例、生产或测试环境、当前数据归属。已有服务能承载需求就复用。有多个可能的库且无法判定时，只请用户指出目标项目或实例名。新应用通过自己的表、集合或命名空间隔离业务数据。个人学习应用的数据库和口令不随技能复用。
- 定下账号、设备和数据之间的关系。同一个人登录两台手机时，两台设备分别持有会话，读取相同用户 ID 的记录。接入既有身份服务，服务端按会话身份授权；面向浏览器的托管数据库 SDK 使用普通客户端凭证和行级权限，管理密钥留在服务端。账号开通、会话登录、数据同步分别显示结果。
- 界定哪些数据上云、哪些只留在本机，尤其是录音、媒体和未提交草稿。旧设备已有数据时，先保留可恢复副本，再做首次登录合并或数据格式迁移。原域名、存储键、旧版备份格式有实际用户时，升级要兼容它们。

## 怎样把两台设备接起来

- 一次用户操作先可靠落盘。需要离线使用时，把待提交操作和重试标识一起保存。界面可以依次显示「已存本机」「待上传」「已保存到云端」及最近确认时间。另一台设备拉取并显示同一版本后，才有双机一致的证据。响应丢失后用同一标识重试，保证一次操作只计一次。
- 按数据含义决定冲突规则。独立新增的打卡可以按事件 ID 去重合并。同一段笔记被两台设备离线改写时，保留两份并让用户选择。已有服务提供事务、版本号或条件写入时优先复用。仅对确实需要独占的编辑使用写入租约，其他设备仍可读取已确认数据。
- 空白新机首次登录先拉取云端。旧机首次登录要同时考虑本机与云端已有记录。若旧数据尚无账号归属，先让用户认领到正确账号再合并。验证两台设备交替使用、并发或断网重连后仍能恢复，落盘失败、登录过期、网络超时和冲突都应给出能执行的下一步。

## 手机网页版如何升级

继续使用稳定 HTTPS 入口；需要从国内手机直连时按实际网络验证可达性。发布时先上传同一版本的全部资源，再切换首页入口。保留仍有旧标签使用的资源和新旧客户端都能读取的数据格式。涉及云库迁移时先做可恢复备份，在隔离环境验证升级与恢复，再执行已获授权的上线操作。

网页首次打开、切回前台以及手动同步成功后，可以分别检查新版本。对首页或版本信息使用新鲜响应，静态资源使用版本化地址。同版本保持当前页面。切换时保留当前功能路由，等写入完成、播放或录音结束、编辑内容可恢复再加载新版。早于版本检测功能的旧页面需要在原浏览器打开一次同源新版入口。排查时提供直达**用户要看的功能页**的链接，并给一个可以辨认版本的标记。

## 用一个真实动作验收

挑应用里最重要的一件事，在两台隔离客户端做一趟往返。A 新增一条，B 登录同一账号看见它；B 改一处，A 再打开能看见这次修改；发布新版后，原入口、原账号和这条记录仍能使用。测试优先用测试账号及合成数据。若用户反馈来自真机，结合对方看到的页面和数字复核，交付时区分已发布、模拟验证和用户已确认的范围。

遇到「有账号但没数据」「已同步但界面旧」或需要设计验收时，按 [跨设备验收与排查](references/acceptance.md) 选择对应场景。
