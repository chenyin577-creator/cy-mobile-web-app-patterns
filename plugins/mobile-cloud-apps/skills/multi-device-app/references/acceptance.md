# 跨设备验收与排查

每个场景都选一条可识别的业务记录。云库若用于多个应用，比较时同时核对应用范围、所属账号和记录 ID。登录页上的账号名称只能回答身份问题。

| 场景 | 做什么 | 怎样算通过 |
| --- | --- | --- |
| 新设备加入 | A 写入一条测试记录并等服务端确认，再用空白浏览器 B 登录 | B 在业务页面看见同一条内容；A 的会话仍可使用。新机的空状态没有覆盖云端 |
| 换机后接着改 | B 更新同一条记录，A 切回前台 | 两端显示相同的业务结果，刷新后还在；操作重试不会多出一条 |
| 离线和冲突 | A 断网编辑，B 在线编辑，然后 A 重连。另测一次服务端已收到写入但客户端没收到回执 | 能自动合并的内容都在；互相矛盾的改动可分别找回；重试不丢不重 |
| 从真实旧版升级 | 在上一发行版先留下记录和播放位置或草稿，保持页面打开，再切换到新版 | 当前操作安全结束后，在相同域名和原功能页加载新版；旧记录、会话及可恢复内容保留 |
| 换账号（支持多用户时） | 在同设备上把 A 账号切换为 B，再尝试打开 A 的记录 | 服务端拒绝越权访问；本机待同步数据仍归原账号，B 看不到 A 的私有数据 |
| 用户使用主屏幕图标 | 分别从用户实际使用的浏览器和主屏幕入口进入，记录各自显示的版本 | 能确认正在使用哪个入口、会话以及本机数据。遇到不同存储环境时，先保护有历史记录的那一份 |

## 手机显示不一致时

1. 先确定用户在看哪个页面。问一句能分支的问题，例如「学习页顶部显示百分比、写着今天没有任务，还是只显示几关到期？」需要示例时用这台设备应有的真实结果；截图只截业务卡片。
2. 在原浏览器、相同域名下给直达该功能的链接。线上核对入口指向的构建；手机若仍运行较旧的代码，可以用带新查询参数的同源入口重新加载。保留原标签中未保存的工作。避免清缓存、注销、重注册或强制覆盖数据作为首步。
3. **账号存在**看身份接口响应。**这台已登录**看设备的有效会话。**已保存到云端**看该次写入的版本或回执。**两台都已更新数据**看另一台实际拉到的版本和页面值。页面若只写「已同步」，查清它对应哪一步。
4. 页面版本一致但业务数字不同，按同一账号、数据范围、时区和日期比较已保存的云端汇总与设备实际显示。确认哪一端有尚未上传的操作。保留原数据后按业务语义解决差异。
5. 若出现「暂未连接」，区分网络、会话过期、本机存储失败、数据校验和冲突。优先用不写数据的版本检查与会话检查缩小范围。对外只回报必要的状态、时间、版本和汇总；凭据不进入聊天、日志、技能文件或前端包。

交付时给一个日常入口、一项用户可核对的业务结果，并说明在哪些设备上观察到了它。
